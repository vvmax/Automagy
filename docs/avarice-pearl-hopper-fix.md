# Исправление повторного подбора Avarice Pearl

Исторический отчёт для сборки `pearl-fix.1`. Текущая сборка, команды проверки и полный список исправлений описаны в [fixes-release.md](fixes-release.md).

Для Automagy 0.28.2, Minecraft 1.7.10, Forge 10.13.4.1614.

## Причина

`TileEntityHopper.func_145898_a` переносит копию стека в инвентарь. Если перенос полный, он вызывает `EntityItem.setDead()`, но не обнуляет старый стек внутри сущности. До удаления сущности из списка чанка она всё ещё доступна запросам с пользовательским фильтром.

Старый `EntityAvaricePearl.EntitySelectorItem` проверял только `instanceof EntityItem`. Поэтому предмет, уже собранный воронкой, мог попасть в выборку жемчужины со старым положительным количеством. `EntityItem.onCollideWithPlayer` в Forge 1.7.10 не проверяет `isDead` перед передачей стека игроку.

Фильтр теперь исключает мёртвые сущности, отсутствующие предметы и стеки с количеством <= 0. Перед подсчётом количества и переносом каждого элемента снимка выборки состояние проверяется повторно. Проверки действуют при ударе жемчужины и при продолжающемся сборе Miser's Pearl. Вызов штатного подбора, события Forge, NBT и лимит 10 стеков сохранены.

## Сборка

Требуются Python 3, Gradle 9.2.0, JDK 8 для мода/тестов и JDK 17 для remapper. Gradle запускается на Java 17 или новее. Укажите пути к JDK через `JAVA8_HOME` и `JAVA17_HOME`.

```bash
python3 tools/fetch-inputs.py
gradle test patchedJar
python3 tools/verify-pearl-fix.py
```

В подготовленном облачном окружении вместо `gradle` можно использовать:

```bash
/workspace/minecraft-1.7.10/bin/mc-gradle test patchedJar
```

Результат: `build/libs/Automagy-1.7.10-0.28.2-pearl-fix.1.jar`.

Сборка компилирует исправленный класс, переводит его в SRG через RetroFuturaGradle 2.0.6 и заменяет только его и вложенный фильтр в закреплённом официальном JAR. Все остальные 437 классов и 241 ресурс остаются побайтово исходными. Это полноценный JAR мода, а не дополнительный мод для одновременной установки с Automagy. Внутренний номер версии мода оставлен 0.28.2; для различения используйте имя и SHA-256 файла.

## Автоматические проверки

Восемь тестов используют реальные `EntityItem`, `ItemStack`, `InventoryBasic` и код переноса воронки Minecraft/Forge. Для вызовов мира используется Mockito, без запуска сервера:

- полный подбор воронкой оставляет старый стек в мёртвой сущности; фильтр жемчужины обязан его отклонить;
- частичный подбор сохраняет только остаток, metadata и NBT;
- пустые/отрицательные стеки и сущности других типов отклоняются;
- удаление сущности между выборкой и ударом не приводит к переносу;
- живые предметы переносятся без изменения количества и самого стека;
- 16 жемчужин не используют повторно предмет после подбора воронкой;
- продолжающийся сбор повторно проверяет состояние снимка;
- лимит Miser's Pearl остаётся равным 10 стекам.

Для сравнения с исходным кодом предусмотрен параметр `-PpearlSourceRoot=<каталог исходников>`. Исходная декомпиляция требует одного исправления типов для компиляции: результат `selectEntitiesWithinAABB` нужно предварительно присвоить `List<Entity>` перед последним циклом. Это не меняет поведение фильтра или переноса.

`tools/verify-pearl-fix.py` проверяет состав JAR, неизменность остальных файлов, целостность ZIP и SRG-имена в исправленном фильтре.

Проверка в этом окружении: на исходном коде пять из восьми тестов завершаются ошибкой; после исправления проходят все восемь. Итог и SHA-256 JAR записаны в `logs/pearl-fix-validation.json`.

## Установка и проверка в игре

Остановите тестовый сервер и сохраните используемый Automagy JAR. Замените официальный Automagy 0.28.2 собранным файлом: в каталоге `mods` должен остаться один Automagy. Если сервер использует свою модификацию Automagy, перенесите исправление в неё: данный JAR собран поверх официального релиза и не включает сторонние патчи.

На копии мира повторите сценарий из предоставленного описания: четыре воронки 2×2, исходные 64 целевых блока, серия из 16 Avarice Pearl и выбрасывание предметов во время падения жемчужин. Проведите минимум 20 попыток. Считайте предметы у игрока, в воронках и на земле; проверяйте итог после перезахода и перезапуска. Дополнительно проверьте частично заполненные/полные инвентари, предметы с metadata/NBT, одну жемчужину и обычный сбор без воронок.

Игровое воспроизведение видео и прогон на Sigmarix/Crucible не выполнялись. Автотесты подтверждают обнаруженный путь повторного подбора в коде Forge 1.7.10, но не заменяют проверку конкретного серверного ядра и плагинов.

Для отката остановите сервер и верните сохранённый Automagy JAR. Это отменит патч, но не удалит ранее созданные дубликаты из мира.
